# Product Management Interview Glossary

This glossary gives concise working definitions. Terms can have different meanings across organisations, so clarify context in an interview.

| Term | Practical meaning |
|---|---|
| A/B test | A controlled comparison between experiences, usually with random assignment, to estimate the effect of a change. |
| Activation | The point at which a user or account first experiences meaningful product value. Define it for the product. |
| Adoption | The extent to which a target user or organisation begins using a product or capability. |
| ARPU | Average revenue per user over a defined period. Define the user population and revenue basis. |
| Backlog | A prioritised set of work items or opportunities. A backlog is not automatically a roadmap. |
| Baseline | The reference value used to compare a result. |
| Build vs Buy | A decision between creating a capability internally and using an external solution. |
| Churn | The loss of customers, users, accounts, or recurring revenue over a defined period. Specify the unit. |
| Cohort | A group of users or accounts sharing a defining event or characteristic, often used for retention analysis. |
| Conversion rate | The share of an eligible population that completes a defined action. State numerator and denominator. |
| Cost of Delay | The value or impact lost by waiting to deliver an initiative. |
| Customer journey | The sequence of steps and experiences a customer goes through to achieve a goal. |
| DAU / WAU / MAU | Daily, weekly, or monthly active users. Define what activity qualifies as active. |
| Discovery | Work to understand customer problems, opportunities, and solution hypotheses before committing to delivery. |
| Engagement | The degree or pattern of meaningful product interaction. Avoid equating all activity with value. |
| Experiment | A planned test designed to reduce uncertainty and inform a decision. |
| Funnel | A sequence of steps through which users progress toward an outcome. |
| Guardrail metric | A measure that should not worsen while optimising a primary outcome. |
| JTBD | Jobs to Be Done: the progress a person is trying to make in a particular circumstance. |
| KPI | Key Performance Indicator: a measure selected to track progress toward an important objective. |
| Leading indicator | A measure that may move earlier than the outcome it helps predict. |
| MVP | Minimum Viable Product: the smallest product or test that can create value and generate meaningful learning. It is not an excuse for poor quality. |
| North Star Metric | A measure intended to represent customer value delivered and guide supporting product activity. |
| Opportunity cost | The value of the best alternative not chosen. |
| PRD | Product Requirements Document: a document explaining a problem, users, requirements, constraints, and success measures. Format varies by team. |
| Product-market fit | A condition in which a product meets a meaningful market need strongly enough to support sustained adoption and value. It is not a single universal score. |
| RICE | A prioritisation model using Reach, Impact, Confidence, and Effort. |
| Retention | The share of users or customers who continue to use, renew, or return within a defined period. |
| Roadmap | A communication of product direction, outcomes, sequencing, and confidence. It should not be treated as an immutable feature promise. |
| Segmentation | Dividing users or customers into groups with relevant differences in needs, behaviour, or context. |
| TAM / SAM / SOM | Total Addressable Market, Serviceable Available Market, and Serviceable Obtainable Market. Define scope and assumptions carefully. |
| Technical debt | Future cost created by shortcuts, constraints, or design choices that make change or operation harder. |
| Time to Value | Time taken for a user or customer to experience meaningful value. |
| Trade-off | A choice that improves one dimension while accepting a cost or limitation in another. |
| Unit economics | Revenue and cost understood at a meaningful unit, such as customer, order, transaction, or account. |
| User story | A concise description of a user's need or goal, often used to communicate a requirement. |
| Value proposition | The specific value a product promises to a defined customer compared with alternatives. |
